# This fork

This repository is a **fork of
[GMOD/jbrowse-components](https://github.com/GMOD/jbrowse-components)**
maintained for BioSeek: a genome browser that is pleasant for people to use and
that an AI agent can drive through a scriptable API. Upstream moves fast; this
document is what keeps the fork from becoming an unmergeable pile.

Three questions it answers, in order:

1. **What does this fork change?** — the feature groups below, with a
   mergeability judgment per group, and `FORK_MANIFEST.md` for the exact,
   generated file list.
2. **Are we up to date?** — the upstream sync point and how to move it.
3. **How do I rebase without losing something?** — the checklist at the end.

The intentional product decisions (things a reviewer might mistake for bugs) are
recorded in [`CLAUDE.md` § Fork divergences](./CLAUDE.md#fork-divergences). This
file is about _files and merge risk_, not about UI decisions.

## Feature groups

Each row is a coherent change set: what it is, the files that carry it, whether
upstream would plausibly take it, and what to watch at rebase time.

### 1. FeatureChartTrack and the chart plugin — `plugins/feature-chart` (99 paths)

A new track type that draws one small chart per feature
(box/violin/bar/histogram), rendered on canvas and, for the maximize dialog, as
interactive Plotly — both from one `ChartModel`. Plus a declarative
`renderer.spec` vocabulary (v1, frozen), plugin-contributed drawers,
`drawerOptions`, the maximize dialog with PNG/SVG export, and a render cache.

Key files: `plugins/feature-chart/src/FeatureChartDrawer/*` (catalog, chart
spec, painters, color schemes), `FeatureChartRenderer/*`,
`FeatureChartPlotlyRenderer/*`, `LinearFeatureChartDisplay/*`,
`FeatureChartAdapter/*`, `SPEC.md`, `ARCHITECTURE.md`, `FeatureChartTrack.md`,
`CHANGELOG.md`.

Also in this group: `test_data/feature-chart/**` (15 paths, demo fixtures and
the runnable no-build plugin), `component_tests/app-vite/**` (8 paths),
`website/docs/config/*FeatureChart*` (generated), and the `corePlugins`
registration in the three products.

**Upstream mergeability: low as a whole, medium for pieces.** Upstream has no
chart track; the whole feature is fork scope. Two pieces are separately
presentable: `packages/core/src/util/renderTemplate.ts` (generic, see §2) and
the `PluginManager`-scoped drawer catalog pattern (maybe 200 lines). The Plotly
renderer depends on `plotly.js-dist-min`, which upstream deliberately does not
bundle, so it would be a plugin-author decision at best.

**Rebase notes:** conflicts land in `plugins/feature-chart/src/index.ts` (export
list), the three `products/*/src/corePlugins.ts` files, and
`website/docs/config/FeatureChart*.md` (regenerated — never hand-merge those,
run `pnpm configdocs`). `SPEC.md` v1 is a compatibility promise: if upstream
renames a data-shape or palette, adapt at the boundary, do not edit the frozen
vocabulary.

### 2. Generic track info — `packages/product-core/src/ui` + core slots (≈25 paths)

`formatAbout.info` (markdown template, `{{path}}` + `jexl:`), `showInfo`,
`hideUris`, root-level defaults, the markdown renderer with a URL allowlist, and
the `Core-trackInfoContext` extension point. Used by every track type, not just
feature charts.

Key files:
`packages/product-core/src/ui/{trackInfo,MarkdownContent,MarkdownPanel,markdownUrlTransform,markdownToPlainText}.ts(x)`,
`packages/product-core/src/RootModel/FormatAbout.ts`,
`packages/core/src/pluggableElementTypes/models/baseTrackConfig.ts` (the
`formatAbout` slots), `packages/core/src/util/renderTemplate.ts`,
`products/jbrowse-web/src/trackInfoBridge.ts`.

**Upstream mergeability: medium-high** — a generic "track description" slot is a
request upstream gets. The blockers are taste (naming, whether `jexl:` belongs
in this slot) rather than architecture; a PR with the core slots,
`renderTemplate` and the markdown panel would be reviewable. The
`window.__jbrowseTrackInfo` bridge is fork-specific and should be split out of
any PR.

**Rebase notes:** `baseTrackConfig.ts` is a popular upstream file — expect
conflicts in the slot block; keep the four slots together and the defaults
(`info: ''`, `showInfo: true`). `AboutDialogContents.tsx` conflicts often; the
fork's `getTrackInfo()` try/catch is deliberate (a broken template must not take
down the dialog).

### 3. Agent SDK — `packages/agent-sdk` + `products/jbrowse-agent` (14 paths)

Plain-JS SDK injected into a running page (`tracks()`, `track()`, `goto()`,
`displayConfig()`, `setConfig()`, `features()`, `exportView()`, `screenshot()`,
`chartDrawers()`, `chartSpecSchema()`, `selfTest()`), the Playwright runner, and
the docs that describe the script model to an AI.

**Upstream mergeability: low** — this is the product differentiator, and it
hard-codes assumptions about the fork's shell (`workspace` route, dockview
layout, `window.JBrowseRootModel`). The `hostContracts.test.ts` sentinels exist
exactly because those assumptions are ours to keep true.

**Rebase notes:** after any app-shell or track-menu change, run
`node products/jbrowse-agent/run.mjs` against the dev server and
`jbrowse.selfTest()`; the SDK fails loudly rather than degrading, but only if
someone runs it. The `index.d.ts` is the API documentation of record — a new SDK
method without a `.d.ts` entry and a `HELP` line is incomplete.

### 4. Single-cell plugin — `plugins/single-cell` (80 paths) + PRDs

New `SingleCellView` (WebGL UMAP), Zarr/AnnData data layer, lasso/rect
selection, gene-expression sidebar and genome↔cell linkage. Includes fixture
Zarr data and its own PRD/PROGRESS notes.

**Upstream mergeability: low now, possible as a separate plugin later.** The
feature set is experimental and churns. It is self-contained under `plugins/`,
which is what makes it cheap to keep rebasing.

**Rebase notes:** `packages/core/src/util/colorPalettes.ts` is shared with the
feature/wiggle color work — a rename there breaks single-cell and the legend
code together. Fixture data under `plugins/single-cell/public/**` is binary and
must never be "fixed" during a conflict resolution.

### 5. App shell rework and icon migration — `packages/app-core` (35), `packages/web-core` (2), `products/*/src` (≈120)

The routed workspace shell (`landing | workspace | recents | settings`)
replacing the classic view mode, dockview tiling, sidebar navigation, product
injection points (`HeaderButtons`, `SettingsCards`), `config.includes`
resolution, and the lucide-react icon migration
(`packages/core/src/ReExports/LucideReExports.ts`,
`packages/core/src/ui/Icons*`).

**Upstream mergeability: very low** — this is a product direction decision, not
a patch. Treat every upstream change to `packages/app-core/src/ui/App/**`,
`products/jbrowse-web/src/components/JBrowse.tsx` and the view model routing as
a manual merge.

**Rebase notes:** the shell owns URL ↔ `session.activeView` sync; upstream edits
to `products/jbrowse-web/src/rootModel/**` and the `urlparams` handling must be
re-read, not merged blindly. Keep `HeaderButtons`/`SettingsCards` as the only
product→shell injection points; upstream will keep adding to the classic toolbar
and that is where the fork keeps losing it.

### 6. Wiggle, GC content and reference-sequence defaults — `plugins/wiggle` (73), `plugins/gccontent` (6)

Multi-wiggle layout cleanup (clustering removed, shared label geometry, legend
consistency), Y-axis left padding, SI prefix casing (`kbp`, `Mbp`), the
reference-sequence track defaulting to the Assembly category, and auto-switching
to GC content when zoomed out.

**Upstream mergeability: medium** — several of these are bug fixes upstream
would take (SI casing, label geometry, legend consistency). The auto-GC switch
is product behaviour and would need a config slot upstream.

**Rebase notes:** `plugins/wiggle/src/configSchema.ts` and
`MultiLinearWiggleDisplay` are under active upstream development; the
d3-hierarchy2 vendored files were **deleted** by this fork (73 paths include
those deletions) — if upstream reintroduces them, take upstream's version and
drop our deletion.

### 7. Synteny follow mode and coloring — `plugins/linear-comparative-view` (39)

Follow-synteny mode with coverage/identity sliders, strand/identity/rainbow
coloring, snapping header sliders, and the synteny color legend.

**Upstream mergeability: medium for the slider snapping and legend, low for the
follow mode** (it changes navigation semantics of a comparative view).

**Rebase notes:** `LinearSyntenyView/util/followSynteny.ts` is the fork's own
module (cheap to keep); the risky edits are inside
`components/LinearComparativeView.tsx` and the header slider components, which
upstream also touches.

### 8. Canvas feature renderer colors and labels — `plugins/canvas` (32), `packages/core` label/palette utils

Native feature coloring (`colorScheme`, `colorField`, `scoreField`,
`scorePalette`, `scoreScale`, `scoreAutoRange`, `colorByCDS`), BED `itemRgb`
normalization, `labelPlacement` (a fork-only slot), shared label geometry
(`featureLabelLayout.ts`), palette/quantile helpers (`colorPalettes.ts`), and
the data-backed legend (`legendData` in the render result).

**Upstream mergeability: medium-high** for BED `itemRgb` normalization and the
palette helpers (self-contained, no product opinion); low for `labelPlacement`
and the "Color by…" menu shape.

**Rebase notes:** the right-click feature context menu is **removed on purpose**
(see CLAUDE.md), and `LinearBasicDisplay/model.test.ts` locks that in — an
upstream merge that restores `onFeatureContextMenu` will look like a conflict
"fix"; do not take it.

### 9. Assembly and species selection — `packages/core/src/ui`, `plugins/data-management` (39)

Species selector, filtered assembly selectors, assembly selector empty by
default, Autocomplete-based selectors in import forms and the Add-track
workflow.

**Upstream mergeability: medium** — the empty-by-default and Autocomplete
changes are behaviour changes upstream may or may not want; the species selector
is a product feature.

**Rebase notes:** `AssemblySelector` is used by tests across the repo; upstream
snapshot updates and this fork's defaults collide in
`products/jbrowse-web/src/tests/__image_snapshots__/**` — regenerate rather than
merge those.

### 10. Repository mechanics — `(root)` (13), `config/` (2), `webpack/` (1), `website/docs/models` (9)

`CLAUDE.md`, `FORK.md`, `FORK_MANIFEST.md`, `scripts/check-core-plugins.mjs`,
`scripts/fork-manifest.mjs`, jest config (`config/jest/*`), eslint config,
`.gitignore`/`.ignore`/`.prettierignore` entries for generated and agent
artifacts, and the regenerated state-model docs. The root also holds strategy
notes that are deliberately not part of the website: `jbrowse-ai-era-gaps.md`,
`jbrowse-ai-mcp-design.md`, `PRD-jbrowse-py.md`, `layout.md`,
`jbrowse2-ui-prototype.html`.

**Upstream mergeability: n/a** — repo mechanics stay in the fork. If upstream
adds an equivalent script (e.g. a config-docs drift check), prefer theirs and
delete ours; `FORK.md` + manifest would then shrink accordingly.

## Rebase checklist

Do these in order when merging upstream. Skipping step 2 is how `FORK.md` goes
stale; skipping step 5 is how the fork silently loses behaviour.

1. **Merge, do not rebase.** `git merge upstream/main` on a branch, resolve, run
   the suite, then merge to `main`. A rebase of 49 fork commits over a moving
   upstream is not worth it.
2. **Move the sync point.** Update `UPSTREAM_BASE` in
   `scripts/fork-manifest.mjs` to the newly merged upstream commit, run
   `node scripts/fork-manifest.mjs`, and re-read the generated list. Files that
   disappeared were taken over by upstream: delete their rows from the feature
   tables above.
3. **Re-read `FORK.md` § "Feature groups"** against the manifest diff. If a
   group shrank to nothing, delete it; if upstream adopted a piece, say so in
   the row (that is the "upstream would take this" answer arriving for free).
4. **Expected conflict hot spots**, from the group tables:
   `products/*/src/corePlugins.ts`,
   `packages/core/src/pluggableElementTypes/models/baseTrackConfig.ts`,
   `packages/app-core/src/ui/App/**`,
   `products/jbrowse-web/src/components/JBrowse.tsx`,
   `plugins/wiggle/src/configSchema.ts`,
   `plugins/linear-comparative-view/src/LinearComparativeView/**`,
   `plugins/canvas/src/CanvasFeatureRenderer/**`,
   `packages/core/src/util/{colorPalettes,featureLabelLayout}.ts`. Regenerate,
   never hand-merge: `website/docs/config/**`, `website/docs/models/**`,
   `products/jbrowse-web/src/tests/__image_snapshots__/**`.
5. **Do not lose the fork guards** (each one exists because something broke):
   - removed feature context menu (`LinearBasicDisplay/model.test.ts`)
   - BED `itemRgb` normalization + `scoreNormalized`
   - `renderTemplate` `{{path}}` behaviour and the dev-build warning
   - `formatAbout.info` root inheritance and `showInfo` precedence
   - SDK `hostContracts` sentinels and `selfTest()` checks
   - `FeatureChartPlugin` in all three `corePlugins`
6. **Run the checks** (they are all local, no CI needed to know where you
   stand):
   ```bash
   pnpm lint && pnpm typecheck
   pnpm configdocs && pnpm prettier --write website/docs/config && git diff --exit-code website/docs/config
   node scripts/check-core-plugins.mjs --verbose
   node scripts/fork-manifest.mjs --check
   npx jest --selectProjects default --testPathPatterns 'feature-chart|agent-sdk|product-core'
   ```
   Plus the manual product matrix (web / desktop / react-app) when the change
   touches the shell, tracks or plugin registration.
7. **Update the changelog** (`plugins/feature-chart/CHANGELOG.md`) when a config
   surface changed: default values, new slots, deprecations.

## Known upstream conversation starters

If someone wants to reduce this fork, these are the pieces with a real chance:

| piece                                         | why upstream might want it                                | main objection                      |
| --------------------------------------------- | --------------------------------------------------------- | ----------------------------------- |
| `renderTemplate` + `formatAbout.info` slots   | track descriptions are a recurring upstream request       | slot naming, `jexl:` in a text slot |
| BED `itemRgb` → `color` + `scoreNormalized`   | fixes a real inconsistency between BED and other adapters | changes rendered output by default  |
| multi-wiggle label/legend consistency         | pure bug fixes                                            | none, split into small PRs          |
| config-docs drift check in CI                 | cheap, catches a class of PR mistakes                     | CI time (one generator run)         |
| `PluginManager`-scoped drawer catalog pattern | generalizes to other future "catalog" plugins             | no second consumer yet              |

Everything else (chart track, agent SDK, single-cell, app shell, feature
coloring UI) is fork product scope; treat it as "we maintain this" rather than
"upstream owes us a review".
